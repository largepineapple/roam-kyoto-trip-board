# 漫游清单 · 京都

## 目标与衡量

面向正在准备京都旅行的用户，把出游落地任务、执行日期和地点放在同一页。演示是否有用，看三件事：能在一分钟内新增并完成一项任务；刷新后记录仍在；能导出一份包含全部任务的 Markdown 清单。路线预览帮助理解任务与地点的关系。

## 怎么跑

需要 Python 3。在仓库根目录执行一条命令：

```bash
python -m http.server 5173
```

浏览器打开 <http://localhost:5173>。Windows 若只安装了 `py` 启动器，可改用 `py -m http.server 5173`。无构建流程、无依赖安装、无在线地图服务。

## 做了什么

- 新增、删除、完成/恢复待办；更改自动写入浏览器 `localStorage`，刷新后保留。
- 每项有执行日期和京都五个预设地点；过去日期在提交时被阻断并显示错误，日期控件也限制最小日期。
- 点击任务，在右侧京都示意地图上播放从京都站至关联地点的路线绘制与移动点动画；支持减少动态效果的系统偏好。
- 一键下载全部待办为 `.md`，按日期排序并保留完成状态。
- 响应式布局与基础键盘操作。

## 我的假设

- 负责人要展示可信的可用流程，因此先实现真实的待办功能；“多端联动”没有后端与账号条件，本版本明确标注为本机保存，不模拟同步。
- 地图是离线示意图，不是精确道路地图或导航服务；新任务从五个预设地点选择，路线都从京都站出发。
- “日期早于系统当前日期”按用户设备**本地日历日期**判断；今天允许提交。示例任务相对今日生成。
- 首次访问显示三条演示任务；用户清空后会记住空清单，不会再次补种。

## 没做什么及原因

- 未做真实地图、地理编码和导航：需要地图数据与 API，30 分钟内先保证可离线稳定演示。
- 未做账号、云端同步、跨设备联动：需要鉴权与后端，不能把本地存储误称为多端同步。
- 未做编辑任务：增删、状态、日期校验、导出优先覆盖核心流程。

## 已知风险

- `localStorage` 只在当前浏览器与设备保留，清除站点数据会丢失任务；隐私模式或存储被禁用时刷新后可能丢失。
- 路线是预设示意路径，不能用于现实行走决策。
- 设备日期或时区设置错误会影响日期校验。

## 再给 2 小时我会怎么做

先加任务编辑、导入 Markdown 和端到端测试，再用真实地图数据替换示意路线；若确实需要多端联动，再引入登录和后端同步，并处理离线冲突。
